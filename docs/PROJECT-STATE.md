- **M1b implementation:** Runtime provider order is Groq -> Gemini key 1 -> Gemini key 2 -> offline parser. Groq obtains active models from `/openai/v1/models`, prefers the configured model or larger instruct/versatile model candidates, and caches success. Gemini uses per-key-slot/model budgets of 18 requests/day and 4/min by default; daily counters roll at Pacific midnight. Retries are bounded, transient 429 observes Retry-After, and provider failures are persisted as cooldowns. Common tool definitions translate into Gemini and OpenAI-compatible schemas. Successful tool results can return local user messages without a second LLM phrasing request. Attempts record provider/model/status; the engine label shows provider/model/status or degraded fallback reasons.
